# ТЗ: Telegram-бот к языковой модели

Домашнее задание №2 курса «Тренинг для Fullstack-программистов» (coders.su),
выдано на звонке 3 «Контекст и память», 2026-08-17.

Этот файл — **единственный промпт**, которым генерируется проект.
Отправляется агенту одним сообщением, целиком.

Задание №4 (агентный цикл, инструмент exec, файлы-скиллы) делается поверх этого же
репозитория отдельной веткой, поэтому здесь заложен сменный бэкенд модели.

---

<objective>
Разработать готовый к использованию Telegram-бот, который принимает текстовое сообщение
пользователя, отправляет его в локальную языковую модель по OpenAI-совместимому API
и возвращает ответ обратно в чат. Учебный проект: цель — понять устройство петли
Bot API → LLM → ответ, а не собрать максимум функций.
</objective>

<constraints>
Реализуй полностью, без уточняющих вопросов.
Неоднозначность — выбери вариант, запиши в README, продолжай.
Не используй псевдокод: весь код должен запускаться.
В конце прогони pytest и покажи вывод.
</constraints>

<stack>
Python 3.11+.
Зависимости: aiogram 3.x, openai, anthropic, python-dotenv.
Для тестов: pytest, pytest-asyncio.
Больше ничего не ставить. venv + requirements.txt.
</stack>

<architecture>
Модульная структура:
  bot.py            — точка входа, регистрация хендлеров, запуск polling
  config.py         — чтение и валидация переменных окружения
  llms/__init__.py  — call_llm(prompt) -> str: выбор провайдера, единая точка вызова
  llms/ollama.py    — реализация для локальной модели
  llms/anthropic.py — реализация для облачной модели
  tests/

Пакет llms/ — единственное место, знающее про API моделей.
bot.py импортирует только call_llm и о провайдерах ничего не знает.
Смена бэкенда = смена переменных окружения, без правок кода.
Имена функций — snake_case по нормам Python.
</architecture>

<statelessness>
ВАЖНО: бот работает БЕЗ ПАМЯТИ. Каждое сообщение обрабатывается как независимый запрос:
system prompt + текущее сообщение пользователя. История диалога не хранится и не передаётся.
Это требование задания, а не упрощение. Не добавляй хранение истории, БД, кэш диалогов
и не предлагай их в README как «улучшение».
</statelessness>

<llm_backend>
Модель подключается как сменный бэкенд. Единственная точка вызова — call_llm(prompt)
в llms/__init__.py. Поддержать ДВА провайдера, выбор через переменную LLM_PROVIDER:

  LLM_PROVIDER=ollama      локальная модель (по умолчанию)
  LLM_PROVIDER=anthropic   облачная модель

**ollama** — через OpenAI-совместимый клиент (пакет openai, AsyncOpenAI).
Ollama и vLLM оба отдают совместимый /v1, поэтому код для них общий.

**anthropic** — через официальный SDK (пакет anthropic, AsyncAnthropic),
модель по умолчанию claude-opus-5. Не пытаться ходить в Anthropic
OpenAI-совместимым клиентом — использовать родной SDK.

Добавление третьего провайдера = новый файл в llms/ и одна ветка выбора,
без правок в bot.py.

Переменные окружения:
  LLM_PROVIDER          ollama | anthropic, по умолчанию ollama
  LLM_BASE_URL          по умолчанию http://127.0.0.1:11434/v1   (только для ollama)
  LLM_MODEL             qwen3:1.7b для ollama, claude-opus-5 для anthropic
  LLM_API_KEY           для ollama "ollama" — SDK требует непустое значение,
                        локальные серверы его не проверяют;
                        для anthropic — ANTHROPIC_API_KEY из окружения
  LLM_TIMEOUT_SECONDS   по умолчанию 180
  LLM_MAX_TOKENS        по умолчанию 512
  SYSTEM_PROMPT         по умолчанию "Отвечай по-русски, кратко и по существу."

Первый запрос после старта Ollama долгий: модель грузится в память.
Таймаут 180 секунд именно поэтому, не уменьшать.

qwen3 — reasoning-модель и может возвращать рассуждения в блоке <think>...</think>
перед ответом. Вырезать этот блок из текста до отправки пользователю;
если после вырезания пусто — отправить исходный текст.
</llm_backend>

<boundaries>
Всегда: держать секреты в .env, резать ответ под лимит Telegram, ловить ошибки модели.
Сначала спроси: добавлять зависимости сверх списка, менять транспорт на webhook.
Никогда: коммитить .env, зашивать токен в код, добавлять хранение истории диалога.
</boundaries>

<telegram>
Транспорт — long polling (Application/Dispatcher polling), не webhook:
публичный IP и открытый порт не нужны.

Поведение:
- /start — короткое приветствие с указанием текущей модели
- любое текстовое сообщение — отправить в модель, ответ вернуть в чат
- перед обращением к модели показывать статус "печатает"
- нетекстовые сообщения (фото, стикеры, голос) — вежливо ответить, что понимает только текст

Лимит сообщения Telegram — 4096 символов. Ответы длиннее резать на части
по границе переноса строки, при отсутствии переноса — по границе пробела,
в крайнем случае жёстко по лимиту. Пустой ответ модели — отправить явное
"модель вернула пустой ответ", а не молчать.
</telegram>

<error_handling>
Недоступна модель, таймаут, ошибка сети — ответить пользователю понятным текстом
с указанием, что проверить (запущен ли Ollama, верен ли LLM_BASE_URL), и продолжить работу.
Бот не должен падать из-за ошибки в обработке одного сообщения.
Технические детали (класс исключения) — в лог, stack trace пользователю не показывать.
</error_handling>

<security>
TELEGRAM_BOT_TOKEN читается только из переменной окружения, в коде отсутствует.
Первой строкой .gitignore — .env
Приложить .env.example со всеми переменными и пустым токеном.
Токен никогда не попадает в логи: при логировании конфигурации маскировать.
Отсутствие обязательной переменной — понятная ошибка при старте, а не падение по KeyError.
</security>

<tests>
pytest, сеть не дёргать — клиент модели мокать.
1. call_llm возвращает текст ответа модели.
2. Блок <think>...</think> вырезается из ответа.
3. Ответ длиной 10000 символов режется на части, каждая не длиннее 4096.
4. Резка проходит по переносу строки, а не посередине слова.
5. Пустой ответ модели даёт явное сообщение, а не пустую отправку.
6. Таймаут модели даёт понятный ответ пользователю, исключение наружу не летит.
7. Отсутствие TELEGRAM_BOT_TOKEN даёт понятную ошибку старта.
8. В запросе к модели ровно два сообщения: system и текущее user.
   История не передаётся — это защита требования statelessness.
9. Переключение LLM_PROVIDER=anthropic меняет используемый клиент,
   bot.py при этом не меняется — оба провайдера мокаются.
</tests>
