# Отчёт: аудит токенов агента (задание 6)

Состояние: **инфраструктура готова, замер «до» ещё не снят.** Разделы с цифрами
заполняются после прогонов.

## Решения по неоднозначностям ТЗ

1. **Модель и temperature — параметры замера.** `bench.run --model`
   (по умолчанию `claude-haiku-4-5`) и `--temperature` (по умолчанию `0`);
   оба пишутся в метаданные замера. Причина: `claude-opus-5` из-за адаптивного
   рассуждения отклоняет `temperature` (400), а без детерминизма success rate
   между замерами несравним. В `Config` добавлено поле `llm_temperature`
   (по умолчанию `None` — параметр не отправляется, бот в Telegram работает
   как раньше); провайдеры добавляют `temperature` в запрос только если оно
   задано.
2. **Usage у Ollama.** Проект ходит в Ollama через OpenAI-совместимый `/v1`,
   где счётчики называются `prompt_tokens` / `completion_tokens`. Парсер читает
   сначала нативные `prompt_eval_count` / `eval_count`, затем OpenAI-имена;
   кэша нет — `cached_input_tokens = 0`.
3. **Пятое поле в `Usage`: `cache_write_input_tokens`.** Запись в кэш Anthropic
   тарифицируется ×1.25 к обычному вводу. Без этого поля стоимость замера
   «после» (с prompt caching) была бы занижена, а экономия — завышена.
3a. **`Usage.reasoning_tokens`.** На модели без расширенного мышления поле
   всегда 0. У моделей с мышлением (Anthropic) токены рассуждения уже входят
   в `output_tokens`, отдельно API их не отдаёт — поэтому у Anthropic поле
   тоже 0 и стоимость output их уже включает. Ollama через OpenAI-совместимый
   `/v1` может отдать `completion_tokens_details.reasoning_tokens` — тогда
   значение читается оттуда (справочно, в стоимость отдельно не входит).
4. **Пометка «провайдер не отдал usage»** — поле `usage_missing` в событии,
   вычисляется как «оба счётчика нулевые» (`Usage.is_reported`).
5. **`run_id` и `step` передаются через `contextvars`**
   (`observability/run_context.py`), а не через сигнатуры `call_llm_step` и
   `run_tool`: харнесс меняется на две строки, сигнатуры и существующие тесты не
   трогаются. Вне цикла агента (`call_llm`) телеметрия не пишется.
6. **Прайс — в `bench/pricing.py`** (таблица по моделям, USD за 1M токенов,
   раздельно input / output / cached read / cache write). Локальная и
   неизвестная модель стоят 0.
7. **Раскладка входа по блокам.** API отдаёт только суммарные входные токены,
   поэтому в событие пишутся размер в символах и хеш каждого блока
   (`system`, `tools`, каждое сообщение истории); токены блока оцениваются
   пропорционально его доле в символах. Содержимое команд и выводов в JSONL не
   попадает — только размеры и хеши.
8. **Задача 8 (`ls /nonexistent`).** Абсолютный путь вне рабочего каталога
   отклоняется проверкой путей ещё до запуска, то есть это был бы тот же отказ,
   что в задаче 9. Чтобы команда действительно выполнилась и упала, задача
   просит `ls nonexistent/` относительно рабочего каталога.
9. **Задача 9 (вне allowlist)** — `uname -a`: безобидная команда, которой нет в
   белом списке.
10. **Задача 12** — GET к `https://api.github.com/repos/python/cpython`,
    проверка вхождения `python/cpython` (стабильное поле `full_name`).
11. **Проверка «точное число»** — число как отдельный токен в тексте
    (не часть другого числа), потому что финальный ответ обычно содержит слова.
12. **Файлы замера.** Агрегат `bench/results/<label>.json` (метаданные,
    сводка, timeline одного запуска) коммитится. Сырьё остаётся локально в
    `telemetry/` под `.gitignore`: `<label>.events.jsonl` (телеметрия) и
    `<label>.outcomes.jsonl` (вердикты с обрезанным до 300 символов ответом
    агента). Отчёт и дашборд строятся только из агрегата. Повторный запуск
    с той же меткой отклоняется без `--force` — защита от правки замера «до»
    задним числом. Телеметрия бота вне бенчмарка пишется в
    `telemetry/events.jsonl`, путь переопределяется переменной `TELEMETRY_PATH`.

## Как снять замер

```
source .venv/bin/activate
python -m bench.run --label before --runs 3        # модель claude-haiku-4-5, temperature=0
python -m bench.report --before before            # сводка + дашборд
python -m bench.report --before before --after after
```
