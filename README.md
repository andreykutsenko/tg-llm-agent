# Telegram-бот к языковой модели

Бот принимает текстовое сообщение, отправляет его в языковую модель и возвращает ответ
в чат. Работает **без памяти**: каждое сообщение — независимый запрос
`system prompt + текущее сообщение пользователя`. История диалога не хранится
и не передаётся модели.

Поддерживаются два сменных бэкенда:

| `LLM_PROVIDER` | Транспорт | Модель по умолчанию |
|----------------|-----------|---------------------|
| `ollama` (по умолчанию) | OpenAI-совместимый `/v1` через пакет `openai` | `qwen3:1.7b` |
| `anthropic` | родной SDK `anthropic` | `claude-opus-5` |

Переключение бэкенда — только сменой переменных окружения, код не меняется.

> **Как проверить работоспособность:** нужны только два значения в `.env` —
> `TELEGRAM_BOT_TOKEN` от [@BotFather](https://t.me/BotFather) и, для облачного
> профиля, `ANTHROPIC_API_KEY`. Для локального профиля ключ не нужен, но нужна
> запущенная Ollama с моделью `qwen3:1.7b`. Подробности ниже в разделах
> «Настройка» и «Запуск».

Спецификация, по которой сгенерирован проект — [SPEC-tg-bot.md](SPEC-tg-bot.md).
Замеры токенов и стоимости — [REPORT.md](REPORT.md).

## Структура

```
bot.py            точка входа: хендлеры, нарезка ответа, запуск polling
config.py         чтение и валидация переменных окружения
llms/__init__.py  call_llm(prompt) -> str: выбор провайдера, вырезание <think>
llms/ollama.py    локальная модель через AsyncOpenAI
llms/anthropic.py облачная модель через AsyncAnthropic
llms/errors.py    LLMError / LLMTimeoutError — общие ошибки слоя моделей
tests/            pytest, сеть не используется
```

`bot.py` импортирует только `call_llm` и о провайдерах ничего не знает.
Третий провайдер = новый файл в `llms/` и одна запись в `_GENERATORS`.

## Установка

Python 3.11+. Подойдёт любой из двух способов.

**Через `uv`** — менеджер пакетов на Rust, ставит те же пакеты из PyPI, но быстрее:

```bash
uv venv
uv pip install -r requirements.txt
```

**Штатными средствами Python:**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

> ⚠️ Окружение в разработке создавалось через `uv`, потому что в системе отсутствовал
> пакет `python3.13-venv`. Такое окружение **не содержит `pip`** — это штатное
> поведение `uv`. Если вы получили `No module named pip`, ставьте пакеты
> командой `uv pip install -r requirements.txt` либо пересоздайте окружение
> штатным `python3 -m venv`. Сам `requirements.txt` обычный и совместим с обоими.

## Запуск команд

С активированным окружением:

```bash
source .venv/bin/activate
python bot.py
pytest -q
```

Либо без активации, напрямую интерпретатором окружения:

```bash
.venv/bin/python bot.py
.venv/bin/python -m pytest -q
```

## Настройка

```bash
cp .env.example .env
```

В `.env` заполнить `TELEGRAM_BOT_TOKEN` (токен от @BotFather).
В файле два готовых профиля: локальная Ollama (активен) и облачный Anthropic
(закомментирован). Для облака достаточно раскомментировать второй блок
и закомментировать первый.

Переменные:

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `TELEGRAM_BOT_TOKEN` | — (обязательна) | токен бота |
| `LLM_PROVIDER` | `ollama` | `ollama` или `anthropic` |
| `LLM_BASE_URL` | `http://127.0.0.1:11434/v1` | адрес локального сервера (только `ollama`) |
| `LLM_MODEL` | `qwen3:1.7b` / `claude-opus-5` | имя модели |
| `LLM_API_KEY` | `ollama` | ключ; для anthropic — либо он, либо `ANTHROPIC_API_KEY` |
| `LLM_TIMEOUT_SECONDS` | `180` | таймаут запроса |
| `LLM_MAX_TOKENS` | `512` | лимит ответа |
| `SYSTEM_PROMPT` | «Отвечай по-русски, кратко и по существу.» | системный промпт |

## Запуск локальной модели

```bash
ollama serve          # если сервер ещё не запущен
ollama run qwen3:1.7b # скачает модель и прогреет её
```

Первый запрос после старта Ollama долгий — модель грузится в память.
Именно поэтому таймаут 180 секунд; уменьшать его не следует.

## Запуск бота

```bash
python bot.py
```

Транспорт — long polling, публичный IP и открытый порт не нужны.
Остановка — Ctrl+C.

## Тесты

```bash
pytest
```

Сеть не используется: клиенты обоих провайдеров подменяются моками.

## Принятые решения по неоднозначностям ТЗ

1. **`llms/errors.py` сверх списка модулей.** `LLMError` и `LLMTimeoutError` нужны
   и провайдерам, и `llms/__init__.py`. Держать их в `__init__.py` означало бы
   круговой импорт, поэтому они вынесены в отдельный маленький модуль.
   Наружу они по-прежнему доступны как `from llms import LLMError`.
2. **Клиент создаётся на каждый запрос и закрывается в `finally`.** Бот
   малонагруженный, а переиспользуемый клиент пришлось бы инвалидировать при
   смене конфигурации и в тестах. Утечки соединений нет — клиент закрывается явно.
3. **Статус «печатает» — один вызов `send_chat_action`, а не повторяющийся цикл.**
   Telegram гасит статус через ~5 секунд, при долгом ответе модели он пропадёт.
   Периодическое обновление потребовало бы фоновой задачи на каждое сообщение —
   для учебного бота это лишняя сложность.
4. **`call_llm(prompt, config=None)`.** Второй параметр опционален и нужен тестам,
   чтобы не трогать глобальную конфигурацию. В `bot.py` вызывается строго
   как `call_llm(prompt)` — сигнатура из ТЗ соблюдена.
5. **Вырезание `<think>` живёт в `llms/__init__.py`, а не в провайдере.**
   Reasoning-блоки может отдавать не только qwen3, поэтому очистка общая
   для всех бэкендов. Если после вырезания текст пуст — отправляется исходный.
6. **Нарезка длинных ответов режет по границе и убирает пробелы на стыке.**
   Приоритет: перенос строки → пробел → жёсткий разрез по 4096 символов.
   Пробельные символы на границе кусков отбрасываются, содержимое — нет.
7. **Ошибка конфигурации при старте — сообщение в лог и код возврата 1**,
   а не traceback. Токены в логе маскируются (`describe_config`).
8. **`LLM_MAX_TOKENS` передаётся как `max_tokens` обоим провайдерам.**
   Для Anthropic это обязательный параметр API, для Ollama — ограничение длины.

Памяти диалога нет по требованию задания — это не упрощение, и добавлять её не нужно.
