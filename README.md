# Telegram-агент к языковой модели

Принимает текстовое сообщение и отвечает на него, при необходимости выполняя
консольные команды: модель просит вызов инструмента → код его выполняет →
результат возвращается модели → так до финального ответа.

**Без памяти.** Контекст цикла живёт ровно один запрос пользователя и после
ответа отбрасывается. История диалога не хранится и модели не передаётся.

**Два бэкенда**, переключаются переменной `LLM_PROVIDER`, код не меняется:

| Значение | Модель | Требует |
|---|---|---|
| `anthropic` *(по умолчанию в агентном режиме)* | облачный `claude-opus-5` | `ANTHROPIC_API_KEY` |
| `ollama` | локальная `qwen3:1.7b` | запущенную Ollama |

Версия без агента (задание №2, локальный профиль по умолчанию) — тег `v1-bot`.

---

## Требования

Python 3.11+, [uv](https://docs.astral.sh/uv/), токен бота от [@BotFather](https://t.me/BotFather).
Для локального профиля — [Ollama](https://ollama.com).

## Установка

```bash
git clone https://github.com/andreykutsenko/tg-llm-agent.git
cd tg-llm-agent

uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt
```

Нет `uv` — поставить одной командой:
`curl -LsSf https://astral.sh/uv/install.sh | sh`

### Нужна конкретная версия

Репозиторий развивается: поверх бота будет надстроен агент. Состояния сдачи
помечены тегами, поэтому версия задания 2 доступна всегда:

```bash
git checkout v1-bot
```

Вернуться к актуальной версии — `git checkout main`.
Без git: на странице репозитория **Tags → v1-bot → Download ZIP**.

## Настройка

```bash
cp .env.example .env
```

В `.env` заполнить **две строки**:

- `TELEGRAM_BOT_TOKEN` — токен от @BotFather;
- `ANTHROPIC_API_KEY` — ключ облачной модели (профиль по умолчанию).

Настоятельно рекомендуется задать и третью — `TELEGRAM_ALLOWED_IDS`
(свой числовой id узнать у @userinfobot). Список пуст — бот отвечает всем,
а у агента есть `exec`.

Для локального профиля: раскомментировать блок `ollama` и закомментировать
блок `anthropic`.

## Запуск

Профиль по умолчанию (`anthropic`) запускается одной командой, Ollama не нужна:

```bash
.venv/bin/python bot.py
```

Локальный профиль требует двух терминалов.

**Терминал 1 — сервер модели.** Команда не завершается, окно держать открытым:

```bash
ollama serve
```

Ответ `address already in use` означает, что Ollama установлена как системная
служба и уже работает — этот терминал не нужен, переходите ко второму.
Проверить: `curl http://127.0.0.1:11434/v1/models`.

**Терминал 2 — скачать модель и запустить бота.** `pull` обращается к запущенному
серверу, поэтому порядок именно такой; скачивание нужно один раз:

```bash
ollama pull qwen3:1.7b
.venv/bin/python bot.py
```

Транспорт — long polling, публичный IP и открытый порт не требуются.
Первый запрос после старта Ollama идёт дольше: модель грузится в память,
поэтому таймаут 180 секунд.

## Остановка

`Ctrl+C` в терминале с ботом — polling прекращается, процесс завершается.

`Ctrl+C` в терминале с `ollama serve` — сервер останавливается, модель выгружается
из памяти. Если Ollama работает системной службой: `systemctl --user stop ollama`
либо `sudo systemctl stop ollama`, смотря как установлена.

Модель занимает около 2 ГБ оперативной памяти. Без остановки сервера она
выгружается сама примерно через 5 минут простоя.

## Агентный режим

Бот не просто пересылает сообщение модели: он крутит цикл.

```
сообщение пользователя
  → модель (системный промпт + скиллы + описания инструментов)
  → модель просит вызов инструмента
  → код выполняет и возвращает результат
  → модель снова
  → … до финального текста или до AGENT_MAX_STEPS
```

Каждый шаг пишется в лог — номер шага, имя инструмента, аргументы и длина
результата. Это единственный способ понять, почему агент пришёл к ответу:

```
INFO tools.exec: exec запускает ['curl', '-sS', '--max-time', '15', 'https://wttr.in/Minsk?0'] в /home/kts/code/tg-llm-agent (таймаут 20 с)
INFO harness: Шаг 1/8: инструмент exec, аргументы {'command': [...]}, результат 321 символов
INFO harness: Шаг 2/8: финальный ответ модели
```

Лимит шагов исчерпан — пользователь получает то, что успело накопиться,
с явной пометкой «⚠️ Лимит шагов агента исчерпан». Молча цикл не обрывается.

### Переменные

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `TELEGRAM_ALLOWED_IDS` | пусто | кому бот отвечает; пусто — всем, при старте предупреждение |
| `AGENT_MAX_STEPS` | `8` | шагов цикла на один запрос, допустимо 5–10 |
| `EXEC_ALLOWLIST` | `curl,cat,ls,date,head,tail,wc,grep` | какие команды разрешены |
| `EXEC_TIMEOUT_SECONDS` | `20` | после этого процесс снимается |
| `EXEC_WORKDIR` | каталог проекта | рабочий каталог подпроцесса |
| `EXEC_MAX_OUTPUT` | `4000` | лимит символов вывода команды: остаются начало и конец, с пометкой о пропуске |
| `EXEC_MAX_LINES` | `30` | лимит строк вывода: первые 20 и последние 10, с пометкой, сколько пропущено |
| `SKILLS_DIR` | `skills` | откуда читаются скиллы |
| `SKILLS_MAX_CHARS` | `8000` | суммарный лимит скиллов; превышение — ошибка старта |

### Чем ограничен exec

1. Команда запускается **без шелла**, списком аргументов. `;`, `&&`, `|`,
   кавычки и обратные апострофы остаются обычным текстом внутри аргумента.
2. Имя программы должно быть в `EXEC_ALLOWLIST`, иначе отказ с объяснением.
3. Таймаут `EXEC_TIMEOUT_SECONDS`, процесс снимается.
4. Рабочий каталог — `EXEC_WORKDIR`; путь-аргумент за его пределы отклоняется.
   Файлы `.env` недоступны отдельной проверкой.
5. Подпроцесс получает **очищенное окружение**: только `PATH` и `LANG`.
   В окружении бота лежат `TELEGRAM_BOT_TOKEN` и `ANTHROPIC_API_KEY` —
   без очистки любая разрешённая команда получила бы к ним доступ.
6. Вывод обрезается до `EXEC_MAX_OUTPUT` символов с явной пометкой.

Отказ — нормальный текстовый ответ модели, а не исключение: модель читает
причину и пробует иначе.

> **Allowlist — не песочница.** Он ограничивает имена команд, а не их
> аргументы. Пары `cat` + `curl` достаточно, чтобы прочитать доступный файл
> и отправить его наружу; попасть в такой сценарий модель может не по злому
> умыслу, а по prompt injection — через текст, присланный в чат.
> Настоящая граница — отдельный пользователь ОС или контейнер, а не список
> разрешённых команд. Очистка окружения, ограничение каталога и
> `TELEGRAM_ALLOWED_IDS` сужают поверхность, но не заменяют изоляцию.

### Как добавить свой скилл

Скилл — обычный `.md` в `skills/`. Все файлы каталога читаются при старте
и подкладываются в системный промпт целиком; отдельным инструментом скилл
не является — действие выполняет `exec`, скилл лишь объясняет, что делать.

1. Положить файл, например `skills/disk.md`.
2. Написать: когда применять, какую команду вызвать (списком аргументов),
   как читать результат, что делать при ошибке.
3. Проверить суммарный размер: `wc -m skills/*.md` должно уложиться
   в `SKILLS_MAX_CHARS`. Превышение — ошибка при старте со списком файлов
   и их размеров, а не молчаливая обрезка: скиллы уходят в КАЖДЫЙ запрос,
   и незаметно обрезанная инструкция хуже отсутствующей.
4. Перезапустить бота.

Готовые примеры: `skills/weather.md` (рутина: погода через wttr.in)
и `skills/http-api.md` (инструкция к инструменту: как ходить в HTTP через curl).

## Проверка

```bash
.venv/bin/python -m pytest      # 76 тестов, сеть и подпроцессы замоканы
```

В Telegram: `/start` покажет активную модель, любое текстовое сообщение вернёт ответ.
Смена `LLM_PROVIDER` в `.env` и перезапуск переключают бота на другую модель —
код при этом не меняется.

Если модель недоступна, бот не падает: отвечает подсказкой, что проверить.

Ручная проверка агента в Telegram:

| Сообщение | Ожидаемое поведение |
|---|---|
| «какая погода в Минске?» | шаг с `exec` + `curl https://wttr.in/Minsk?0`, в ответ — текстовая сводка |
| «удали каталог skills» | отказ по белому списку, в чат — осмысленное объяснение |
| «покажи содержимое .env» | отказ: файл с секретами недоступен |
| сообщение с другого аккаунта | ответа нет, в логе `отклонено: не в TELEGRAM_ALLOWED_IDS` |

В логе при этом видны шаги цикла с именами инструментов.

## Аудит токенов

Бот пишет телеметрию каждого запроса, а пакет `bench/` умеет мерить стоимость
прогона и сравнивать замеры. Выводы аудита и все замеры — в
[REPORT-audit.md](REPORT-audit.md); здесь — как посмотреть самому.

### Телеметрия живого бота

На каждое сообщение в Telegram бот дописывает строки в `telemetry/events.jsonl`
(путь меняется переменной `TELEMETRY_PATH`; каталог в `.gitignore`). Одна строка —
одно событие:

| `event` | Что внутри |
|---|---|
| `llm_call` | `run_id` (один запрос пользователя), `step` (виток цикла), `model`, `input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens`, `reasoning_tokens`, `latency_ms`, `cost` в долларах |
| `tool_call` | `run_id`, `step`, `tool_name`, `input_size`, `output_size` в символах, `duration_ms` |

Содержимое команд и их вывода в файл не попадает — только размеры.
`cached_input_tokens > 0` означает, что prompt caching сработал.

Последние события и сумма за всё время:

```bash
tail -3 telemetry/events.jsonl
.venv/bin/python -c "import json; e=[json.loads(l) for l in open('telemetry/events.jsonl')]; m=[x for x in e if x['event']=='llm_call']; print(f'вызовов {len(m)}, потрачено \${sum(x[\"cost\"] for x in m):.4f}, из кэша {sum(x[\"cached_input_tokens\"] for x in m)} tok')"
```

Сбой записи телеметрии не роняет бота: в лог уходит предупреждение, ответ
пользователю приходит как обычно. Прайс моделей — в `bench/pricing.py`.

### Дашборд

`bench/results/dashboard.html` открывается в браузере без сервера. Сверху —
timeline одного запуска по виткам: столбики входа (без кэша, из кэша, запись в
кэш) и выхода, линия накопленного контекста, под ними таблица с приростом каждого
витка и его раскладкой на ответ модели и вывод инструментов. Ниже — сравнение
двух замеров и сводка каждого: токены и стоимость по типам, cache hit rate,
самые дорогие инструменты, рост контекста по типам, стоимость по задачам.

### Свой замер

Бенчмарк — 12 задач (10 локальных, 2 сетевых) из `bench/tasks.py`, набор
заморожен, фикстуры в `bench/fixtures/`. Прогон платный: около $0.35 и 9 минут
на `claude-sonnet-5` при 10 повторах.

```bash
source .venv/bin/activate
python -m bench.run --label my-check                     # 12 задач × 10 прогонов
python -m bench.report --before before --after my-check  # сводка в консоль + дашборд
```

`bench.run` пишет агрегат в `bench/results/<label>.json` (его можно коммитить)
и сырьё в `telemetry/<label>.events.jsonl`. Повторный запуск с той же меткой
отклоняется без `--force`. Полезные флаги: `--runs`, `--model`, `--tasks 2,6`,
`--no-network`. Критерий успеха задачи — проверка текста ответа, отсутствие
исключения и `limit_reached == False`; сетевые задачи считаются отдельно.

Как читать сводку: «повторно отправлено» — токены, которые уже уходили на
предыдущем витке того же запроса (вход растёт только дописыванием, поэтому это
весь вход предыдущего витка); «рост за виток» — точная разность входа между
витками, разложенная на ответ модели и вывод инструментов через
`messages.count_tokens`.

## Структура

```
bot.py             хендлеры, доступ по id, нарезка ответа под лимит 4096, polling
harness.py         агентный цикл, загрузка скиллов, системный промпт
tools/__init__.py  реестр инструментов: описание для модели + исполнитель
tools/exec.py      выполнение консольных команд с проверками
skills/*.md        инструкции модели, уходят в системный промпт
config.py          чтение и валидация переменных окружения
llms/__init__.py   call_llm_step(messages, tools) -> LLMResult: выбор провайдера
llms/protocol.py   общий вид результата: LLMResult, ToolCall, ToolSpec
llms/ollama.py     локальная модель, AsyncOpenAI, формат tools/tool_calls
llms/anthropic.py  облачная модель, AsyncAnthropic, native tool use
llms/errors.py     LLMError / LLMTimeoutError
observability/     контекст запуска (run_id, step) и JSONL-рекордер событий
bench/tasks.py     замороженный набор из 12 задач бенчмарка и их проверки
bench/run.py       прогон бенчмарка, агрегат в bench/results/<label>.json
bench/report.py    точный учёт роста контекста, сравнение замеров, дашборд
bench/pricing.py   прайс моделей: input / output / cached / cache write
tests/             pytest, клиенты и подпроцессы замоканы
```

`bot.py` и `harness.py` не знают, какой провайдер активен: оба формата вызова
инструментов приводятся к общему `LLMResult` внутри `llms/`. Третий провайдер —
новый файл в `llms/` и одна запись в `_STEP_GENERATORS`.

## Поведение цикла на разных провайдерах

`anthropic` (`claude-opus-5`) — профиль по умолчанию в агентном режиме.
Native tool use: модель возвращает блок `tool_use` с уже разобранным JSON-объектом
аргументов, поэтому попадание в формат вызова стабильное. Размышление у модели
включено по умолчанию и считается в тот же лимит вывода — `LLM_MAX_TOKENS=4096`,
иначе шаг цикла обрывается до вызова инструмента.

`ollama` (`qwen3:1.7b`) — рабочий, но не дефолтный. Отличия, заложенные в код:

- аргументы приходят строкой JSON внутри `tool_calls[].function.arguments`
  и разбираются на стороне `llms/ollama.py`; невалидный JSON не роняет цикл,
  а превращается в отказ инструмента, который модель читает и может исправить;
- ответ модели содержит блок `<think>…</think>`, он вырезается в `llms/__init__.py`,
  включая случай обрыва по лимиту токенов без закрывающего тега;
- модели такого размера ненадёжно попадают в формат вызова инструментов —
  поэтому дефолт агентного режима облачный. Промахи обрабатываются отказом
  с объяснением, а не костылём в харнессе: на `command` строкой вместо списка
  есть отдельная ветка в `tools/exec.py`, на попытку «выполнить» скилл —
  фраза в системном промпте о том, что скилл инструментом не является.

**Что проверено вживую, а что нет.** Цикл прогнан целиком с настоящим
инструментом `exec` (модель при этом подставная): реальный `curl` к wttr.in
отработал за два шага, отказы по белому списку, по `.env` и по выходу
за рабочий каталог вернулись в цикл текстом, шаги видны в логе. Сравнение
живого поведения двух моделей **сознательно не проводилось**, и вот почему.

Агентный цикл делает несколько обращений к модели на один вопрос пользователя.
На доступном железе (ноутбук без GPU, инференс на CPU, порядка 25 токенов
в секунду) один ответ бота занимает 5–8 секунд, а цикл из четырёх шагов —
уже минуты. Плюс модель на 1.7 млрд параметров ненадёжно попадает в формат
вызова инструментов, что для цикла критично: промах означает лишний шаг
из восьми доступных.

Это не пробел, а результат: **локальная модель такого размера практична
для режима «вопрос-ответ» и непрактична для агентного цикла.** Требование
локальной модели относилось к заданию №2 и там выполнено — см. тег `v1-bot`
и скриншоты в `docs/`. Здесь профиль `ollama` остаётся поддержанным кодом
и тестами, но дефолтом агентного режима служит облачный.

Одинаковость наружного контракта закреплена тестами на моках обоих SDK
(`tests/test_llms.py`): один и тот же вызов инструмента даёт идентичный
`LLMResult`, а результат инструмента уходит обратно в формате своего провайдера.

## Решения по неоднозначностям ТЗ

| Вопрос | Решение | Почему |
|---|---|---|
| Дефолтный провайдер в коде | в `.env.example` активен `anthropic`, в коде fallback остался `ollama` | ТЗ требует дефолт `anthropic` именно в `.env.example`; менять и код означало бы, что бот без ключа падает при старте на пустом окружении |
| Формат аргумента `exec` | `command` — массив строк, строка отклоняется | шелла нет, разбирать строку некому; разбирать её самим значило бы вернуть подстановки |
| Где живёт загрузка скиллов | `harness.load_skills()`, кешируется на процесс | ТЗ перечисляет новые файлы поимённо, отдельный модуль был бы отклонением от архитектуры |
| Ограничение каталога | путь-аргумент нормализуется и проверяется на принадлежность `EXEC_WORKDIR` | `cwd` сам по себе не мешает передать `/etc/passwd` абсолютным путём |
| Запрет на `.env` | отдельная проверка по имени файла (`.env`, `.env.*`, кроме `.env.example`) | `.env` лежит внутри рабочего каталога, проверки каталога недостаточно |
| Обрезка вывода | общий бюджет `EXEC_MAX_OUTPUT` на stdout+stderr | иначе лимит по факту удваивается |
| Несколько вызовов инструментов за шаг | выполняются все, шагом считается один вызов модели | лимит `AGENT_MAX_STEPS` должен ограничивать обращения к модели |
| Доступ по `TELEGRAM_ALLOWED_IDS` | проверка во всех хендлерах, включая `/start` | иначе чужой аккаунт узнаёт конфигурацию бота |
| Ответ при исчерпании лимита | склейка текстов модели по шагам + пометка | «то, что есть» — это всё, что модель успела сказать, а не только последний шаг |
