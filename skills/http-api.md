# Скилл: обращение к HTTP API через curl

Тип А — инструкция к инструменту. Описывает, как правильно ходить в HTTP
из инструмента `exec`.

## Как вызывать

Команда передаётся списком, шелла нет: перенаправления `>`, конвейеры `|`
и подстановки `$(...)` не сработают, они попадут в аргумент как текст.

```
["curl", "-sS", "--max-time", "15", "-w", "\nHTTP_CODE:%{http_code}", "<url>"]
```

- `-s` убирает индикатор прогресса, `-S` оставляет текст ошибки в stderr;
- `--max-time` держит запрос короче таймаута инструмента;
- `-w "\nHTTP_CODE:%{http_code}"` дописывает код ответа последней строкой —
  без него код ответа не виден, потому что curl печатает только тело.

## Как читать результат

Инструмент возвращает `exit_code`, `stdout` и `stderr`.

- `exit_code: 0` и `HTTP_CODE:200` — данные в `stdout`, можно отвечать;
- `HTTP_CODE:4xx` — запрос неверный: проверьте URL и параметры, повторять
  тот же запрос бессмысленно;
- `HTTP_CODE:5xx` — сбой на стороне сервиса: допустима одна повторная попытка;
- `exit_code: 6` — не разрешилось имя хоста, `exit_code: 28` — таймаут:
  сообщите пользователю, что сервис недоступен, и не уходите в цикл повторов;
- пометка об обрезке вывода означает, что ответ длиннее лимита: сузьте запрос
  (параметры API) вместо повторной загрузки целиком.

## Ограничения

Разрешены только команды из белого списка и только рабочий каталог проекта.
Файлы с секретами (`.env`) недоступны — отказ инструмента окончателен,
обходить его не нужно. Если задача требует запрещённой команды, честно
скажите пользователю, что она недоступна.
